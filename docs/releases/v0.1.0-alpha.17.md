# OpenStitch 0.1.0 alpha 17

The seventeenth alpha of OpenStitch, an independent, cross-platform embroidery design application
for macOS, Windows and Linux, built to work with Brother machines and with designs made in
PE-DESIGN 11. OpenStitch is not affiliated with Brother Industries.

Alpha 17 is a small release of fixes after alpha 16:
- **The Assistant's question card puts its recommended answer first** and marks it; a question
  you leave open takes it.
- **Clearer Assistant wording** on question cards and after you approve a step.
- **A template can no longer be saved over the project that was open.**
- **macOS: Finder thumbnails and Quick Look work again.**
- **The browser version carries its licence notices,** and CI keeps the notices current.

No stitches change in this alpha, and projects open in alpha 16 as before. **It is still an alpha
for testing, not for production work.** Read "Before you sew" below.

## The builds are not code-signed

- **macOS:** the first time, right-click `OpenStitch.app` and choose **Open**, then **Open**
  again. Alternatively, run `xattr -dr com.apple.quarantine /Applications/OpenStitch.app`.
- **Windows:** in the SmartScreen prompt, choose **More info → Run anyway**.

## What changed since alpha 16

### The Assistant

- **The recommended answer comes first (#1205).** On the Assistant's question card, the first
  answer of every question is the one it recommends, marked **Recommended**. Pick any answer or
  type your own as before. A question you leave open, or **Use your judgment**, takes the
  recommended answer, and the Assistant says what it assumed.
- **Clearer wording (#1198):**
  - Answer choices are answers. A choice like "I'll type it" is left off the card; type your own
    answer in the field under the question.
  - When starting a new design or opening one would replace a design whose only unsaved change is
    the conversation, the question says so, instead of reading as if a drawing would be lost.
  - After you allow a step on an approval card, the Assistant is told you approved it, so it no
    longer says it went ahead without asking.

### Fixes

- **macOS: Finder and Quick Look show stitched thumbnails again** for `.pes`, `.osd` and the
  other embroidery files OpenStitch reads (#1182). The thumbnail extension now draws with the
  renderer linked into it; macOS does not let it start the helper program it used before, so
  every thumbnail had failed and Finder showed the plain document icon.
- **A template never saves over your project (#1179).** Opening a template in the Template
  Wizard replaced the design but kept the file name of the project that was open. The next Save
  then wrote the template over that project.
  - A template now opens as File ▸ New does: an untitled design, so Save asks for a name. If you
    have unsaved changes, you are asked about them first. With "Open designs in tabs" on, the
    template gets its own tab.
  - The same holds when the Assistant or a `--listen` client opens a template.
  - Test swatches never changed the open design or its file, and they still do not. Their
    window's **Open it** now opens the swatch as File ▸ Open does, asking about unsaved changes
    first, where it used to replace the design without asking.

### Licences

- **The browser version shows its third-party notices and licences (#1175).** Help ▸ About in the
  browser version links the third-party notices and the MIT and Apache licences, which the page
  now publishes beside itself. The desktop packages already carry them beside the program.
- **The notices are checked on every change (#1175):** CI fails a pull request whose
  `THIRD_PARTY_NOTICES.md` no longer lists every crate the programs are built from, and prints
  any licence outside the permissive set.

## How it was tested

- **Automatic:** CI runs the full test suite and the compatibility specs on macOS, Windows and
  Linux, including the macOS thumbnail check, which fails when no thumbnail comes back within
  60 seconds; the release workflow builds and smoke-tests each package.
- **The question card** (#1205, #1198) was run live with Claude Code on Windows by the session
  that built it.
- **The Quick Look fix** (#1182) was measured on a Mac on the branch build before it was merged.
- **Not done this time:** nobody checked the macOS release build by hand (the Mac is shut down),
  so macOS rests on CI's thumbnail check and the release smoke test. The Windows MSI needs
  administrator rights and was not installed. The browser version was not run in a real Safari.

## Before you sew

- **Do a test sew-out on scrap fabric** before using a design on anything that matters.
- **Known issues:**
  - **macOS 27: `qlmanage -t` does not reach third-party thumbnail extensions,** so it shows no
    OpenStitch thumbnail from the command line. Finder does show them.
  - **The Assistant panel** has no commands of its own for tests and scripts yet (#1180), and a
    restored chat starts a new coding-agent session instead of continuing the agent's own
    (#1170).
  - **Small local models:** qwen3-vl:4b through Ollama fails to call the Assistant's tools. This
    is a limit of the model; use a larger model or one of the other providers.
  - **The Windows MSI needs administrator rights** to install. The portable zip does not.
  - **The builds are not code-signed** (see above).
  - **Parked for a later alpha:** net fills still differ from PE-DESIGN's stitch counts on some
    shapes (#1043, #1071), and small filled squares sew a few stitches fewer than PE-DESIGN
    (#1131, #1088).
  - Other known differences from PE-DESIGN 11 are in the README's "Known issues" and
    [docs/COMPATIBILITY_AUDIT.md](../COMPATIBILITY_AUDIT.md).
- **Nothing was left out:** no open pull request was held back from this release.
- **Keep your original PE-DESIGN files.** Save OpenStitch's output under a new name.
- **macOS:** double-clicking a file in Finder doesn't open it in OpenStitch yet; use File ▸ Open.

differently from PE-DESIGN 11. After a crash, Help ▸ Report a Problem fills in the version for
you. For sew-outs, use the
[Sew-out / calibration report](https://github.com/cristianonescu/OpenStitch/issues/new?template=sew-out-report.yml)
