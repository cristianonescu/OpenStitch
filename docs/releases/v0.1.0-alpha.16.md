# OpenStitch 0.1.0 alpha 16

The sixteenth alpha of OpenStitch, an independent, cross-platform embroidery design application
for macOS, Windows and Linux, built to work with Brother machines and with designs made in
PE-DESIGN 11. OpenStitch is not affiliated with Brother Industries.

Alpha 16 is a short release of what the owner asked for after alpha 15, mostly in the Assistant
and in how colours and objects are shown:
- **The Assistant sees the pictures you attach,** also when it is a coding agent such as Claude
  Code.
- **The chat is kept with the project:** saving writes the conversation into the `.osd`, and
  opening it lets you go on where you stopped. A setting turns it off.
- **The Assistant asks before it starts** a new design or a large change, with answer chips;
  after each reply it suggests what to say next, and offers **Fix** chips when Check Design
  finds problems.
- **Colours are named by thread code, never by hex value,** everywhere a colour is shown.
- **The Sewing Order list's small pictures look like the objects:** a filled shape is filled.
- **Closing always asks first:** quitting, closing a tab and replacing a design with unsaved
  changes wait for your answer, also when the Assistant does it.
- **A reworked README** for new users, and every document checked against the program.

Projects saved by alpha 16 open in alpha 15, which ignores a kept chat. Stitches change only
where a design names one Brother thread in two ways: those parts now sew as one colour block
(#1197). **It is still an alpha for testing, not for production work.** Read "Before you sew"
below.

Check for Updates. Alpha 3 and earlier must be replaced by hand with a package above.

## The builds are not code-signed

- **macOS:** the first time, right-click `OpenStitch.app` and choose **Open**, then **Open**
  again. Alternatively, run `xattr -dr com.apple.quarantine /Applications/OpenStitch.app`.
- **Windows:** in the SmartScreen prompt, choose **More info → Run anyway**.

## What changed since alpha 15

*Every picture in the docs and the README was regenerated with this release's editor.*

### Scripting and the Assistant

- **A coding agent sees an attached picture (#1168).** With the Assistant set to a coding agent,
  an attached picture reached it only as a file path, while the message told it the picture was
  shown. The agent kept saying it could not see the picture.
  - Claude Code, and any agent that says at start-up that it takes pictures, now gets the
    attached pictures and the View picture in the message, as the Claude API does. They are
    scaled to at most 2048 px and 3.75 MB, as before.
  - An agent that does not take pictures is told so in the message and looks at a picture with
    the new `scratch_view` tool. The chat says the pictures were not sent only in that case.
  - New editor command `ui.scratchView`: a picture in the scratch folder, as the model gets it.

- **The Assistant's conversation is kept with the project (#1169):** saving a design now writes
  the chat into its `.osd`. Opening the project shows the chat again, and you can go on where it
  stopped: your next message carries the earlier conversation to the assistant, with the Claude
  API, OpenAI-compatible endpoints and coding agents alike.
  - **What is kept:** your messages and the assistant's, notices, and each tool step as its
    short label. Not kept: pictures (a message that had attachments says so), the assistant's
    thinking, tool arguments and results, and never a key or token. Your home, temporary and
    scratch folders are written as `~`, `<temp>` and `<scratch>`.
  - **Going on:** the first message after opening sends the last part of the chat (up to 24,000
    characters, whole messages) as quoted text from the file. The assistant is told it is file
    content and not instructions, because a project may come from someone else. A coding agent
    starts a new session with that text; its own earlier tool results are not loaded.
  - **Your control:** "Save the chat with the project" in the Assistant settings and under the
    chat (on by default). Off, nothing is written, and a chat the file already kept is removed
    on its next save. New chat clears the conversation, so the next save keeps none.
  - **Tabs, New, Save As, recovery:** each tab keeps its own chat; New starts an empty one;
    Save As carries it; recovered designs bring theirs back.
  - **Unsaved changes:** while the chat is saved with the project, talking marks the design
    unsaved as an edit does, on any design: the title shows it, closing asks to save, and
    autosave keeps it.
  - **Closing while the assistant works** (#1186) asks first: Stop and close, then the usual
    question about unsaved changes. Quitting, closing a tab and replacing a design with
    unsaved changes always wait for your answer, also under "Allow everything", and can't be
    put on Always allow; the chat names every such command the assistant runs, and a replaced
    design stays in Undo.
  - **Older versions:** alpha 15 opens such a project normally and ignores the chat; saving it
    there drops the chat.
  - **Undo:** a reopened chat does not offer to undo changes from an earlier run of the program.
  - **Saves the assistant runs** keep the conversation as File ▸ Save does (#1176), and the
    assistant knows the setting; clearing the chat stays your action (New chat).
  - **Saves the assistant runs** (#1187): a relative file name is saved beside the design
    (refused while the design has no file), and "Save" from the assistant saves a design that
    already has a file; a note about attachments is no longer repeated on every save.
  - **After its own save** (#1196) the assistant sees the design as saved: the editor's state
    tells design changes from conversation-only ones, so it no longer tells you the save may
    have failed. The rest of its reply is still an unsaved change: closing asks, as before.
  - **Every file the assistant writes lands beside the design** (#1199): an export, a bundle, a
    picture, a thread list, a swatch or a library folder given a relative name was written
    into the program's working folder (on macOS from Finder, `/`). It now goes next to the
    design's own file, the approval card and the chat show the full path, and an untitled
    design is refused until you say where. `stitchtool` on its own keeps its working folder.
  - **Projects the assistant opens** (#1178): the opened file becomes the design's file, as with
    File ▸ Open, and a chat it kept stays in it; a save the assistant runs to a new name makes
    that the design's file, as Save As does.

- **The Assistant asks before it starts, and suggests what to say next (#1172).**
  - For a new design or a large change, it first asks 5 to 10 short questions, such as size,
    fabric, colours, style and lettering. Each has answer chips and room for your own answer.
    **Send answers** sends them; **Use your judgment** lets it go on and say what it assumed. A
    small or fully specified request, such as "make the star red", gets no questions.
  - After every reply: a suggested message (**Send** or **Edit**) and up to four chips with
    things you may want to say next. When the model suggests nothing, a fixed set for how the
    turn ended shows: after an error, with Check Design findings left, after a change, or after
    an answer.
  - When Check Design finds errors or warnings at the end of a turn: **Fix the errors**,
    **Fix the warnings** and **Explain them**. A click sends a message listing each finding;
    the assistant fixes only what has a fix and says what it cannot fix.
  - This works with the Claude API, OpenAI-compatible models and coding agents such as Claude
    Code. A click only sends a message as you, and the usual permission questions still apply.
  - New tools for the model: `ask_user` and `suggest_replies` (editor commands `ui.askUser` and
    `ui.suggestReplies`).

- **A coding agent waits for your answer on an approval card (#1188).** With Claude Code, a
  command that asks first (saving, exporting, opening files) was reported to the agent as "cannot
  reach the editor" after 60 s while its card still waited for you. The agent then sent it again,
  and each retry added another card.
  - The agent's connection now waits as long as the card does (4 minutes), and the agent gets a
    clear answer: you declined, nobody answered in time (it did not run), or the turn ended
    first.
  - The same command sent again while its card is open uses that card: one card, not a stack.
  - The assistant is told to ask you to answer the card instead of retrying or calling the
    editor unreachable.

### Thread colours

- **Colours are named by thread code, never by hex value (#1184).** A swatch, tooltip, list or
  printed sheet now names a colour as a thread: brand, code and name ("New Brothread 205
  Yellow").
  - **Custom colours:** a colour no thread stands behind (an imported SVG's, a DST's, one picked
    by value) shows the code of the nearest thread of your default chart, marked as nearest:
    "≈205" under its swatch and "Custom colour, nearest New Brothread 205 Yellow" in its
    tooltip. The colour itself does not change.
  - **Where:** the swatch captions (Sewing Order, Thread Colours, the colour picker and the
    other colour lists), every thread's tooltip, the thread charts in Settings, the Design
    Database's colour list, the catalogue, the job sheets ("custom colour, nearest …" tells the
    person at the machine which spool to load, and that it is not exact) and Match to Thread
    Chart's list of colours that share a thread. The hex value stays only where you type a
    colour (a chart thread's colour field, the colour picker's hex entry).
  - **The Assistant** names colours the same way. `object.list` gives `regionThread` and
    `lineThread` beside `regionColor` and `lineColor`. `design.info`, `design.timeline`,
    `design.route`, `stitches.points`, `library.info` and the editor's stats give each colour's
    `text`, and a custom colour's `nearest` thread with its ΔE. The hex values stay in the
    replies for scripts.
  - **`design.timeline`:** each block's new `code` is the code on the spool (Brother 800 for a
    PEC chart thread). `number` stays the stored catalogue number, for scripts that read it.
  - **A colour parameter takes a thread code:** `"205"` (the default chart's thread first, then
    Brother's chart, then the other built-in charts) or brand and code (`"Brother 205"`). A code
    two threads of one chart share is refused as ambiguous, naming both. An unknown code is
    refused with the nearest codes, never guessed. A JSON number is still a PEC chart number
    1-64, not a code: 7 is PEC entry 7, and code 007 is `"007"`.
  - **One Brother thread, one colour block (#1197):** a thread named by colour ("Red") and the
    same thread named by its code ("Brother 800") sewed as two colour blocks, with a colour
    change and a machine stop between two identical reds, and the colour list showed the red
    twice. They are now one block, and both read as brand Brother.

### Editing

- **The Sewing Order list's small pictures look like the objects (#1185).** Each row's picture
  showed only an object's outlines, so a filled shape looked like an empty frame. It is now the
  object's own stitches, as the page shows them: a filled shape filled, holes open, satin, text,
  gradients, motif and stamp fills and stitch patterns in all their colours.
  - An object with nothing to show (hidden, or with no sewing) is drawn from its outlines,
    filled in its region colour with its line on top; curves stay curves.
  - A picture in white or near-white thread sits on a grey tile, so it can be seen.
  - The pictures are kept and drawn again only when the object, its colours or the display
    scale change, and only for rows on screen, a few at a time, so a long list never holds up
    typing or dragging. At most 32 MB of them are kept; a dropped one is drawn again when its
    row comes back.

### Documentation

- **The README is reworked for new users (#1171).** Its top says in one sentence what OpenStitch
  is, then shows what you can do with it in twelve short groups with a picture each, then the
  downloads and first steps. The full feature list, the known issues and the plans follow as
  before. A new picture shows Check Design, and another the density map.
- **Every document was checked against the program** (#1171): facts corrected, stale statements
  marked with the date they changed, missing features added.
- **The third-party notices list every crate the programs are built from** (#1171): 469 crates,
  with the full licence texts of the fonts egui draws its interface with and of the two
  BSL-1.0 crates. `tools/third_party.py` keeps the list current.

- **Windows, end to end:** 19 of 19 checks passed on 989a6e17, the final code of this alpha,

## Before you sew

- **Do a test sew-out on scrap fabric** before using a design on anything that matters.
- **Known issues:**
  - **macOS: no Finder thumbnails or Quick Look preview.** It was measured failing on alpha 15
    as well (#1182).
  - **Templates and test swatches keep the open file's path,** so the next Save can overwrite
    your project. Use Save As after opening a template or making a swatch (#1179).
  - **The browser version** publishes no third-party notices file yet (#1175).
  - **The Assistant's wording** on question cards with typed answers, on the replace question
    after a chat-only change, and when it acts without asking, is still to be improved (#1198).
  - **The Assistant panel** has no commands of its own for tests and scripts yet (#1180), and a
    restored chat starts a new coding-agent session instead of continuing the agent's own
    (#1170).
  - **Small local models:** qwen3-vl:4b through Ollama fails to call the Assistant's tools. This
    is a limit of the model; use a larger model or one of the other providers.
  - **The Windows MSI needs administrator rights** to install. The portable zip does not.
  - **The builds are not code-signed** (see above).
  - **Parked for a later alpha:** net fills still differ from PE-DESIGN's stitch counts on some
    shapes (#1043, #1071), and small filled squares sew a few stitches fewer than PE-DESIGN
    (#1131, #1088).
  - Other known differences from PE-DESIGN 11 are in the README's "Known issues" and
    [docs/COMPATIBILITY_AUDIT.md](../COMPATIBILITY_AUDIT.md).
- **Nothing was left out:** no open pull request was held back from this release.
- **Keep your original PE-DESIGN files.** Save OpenStitch's output under a new name.
- **macOS:** double-clicking a file in Finder doesn't open it in OpenStitch yet; use File ▸ Open.

## Feedback

Please open an issue for anything that sews differently from what you expect, crashes, or works
differently from PE-DESIGN 11. After a crash, Help ▸ Report a Problem fills in the version for
you. For sew-outs, use the
[Sew-out / calibration report](https://github.com/cristianonescu/OpenStitch/issues/new?template=sew-out-report.yml)
form, and see [TESTING.md](../../TESTING.md).
