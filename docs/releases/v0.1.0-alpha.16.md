## What changed since alpha 15

### Scripting and the Assistant

- **A coding agent sees an attached picture (#1168).** With the Assistant set to a coding agent,
  an attached picture reached it only as a file path, while the message told it the picture was
  shown. The agent kept saying it could not see the picture.
  - Claude Code, and any agent that says at start-up that it takes pictures, now gets the
    attached pictures and the View picture in the message, as the Claude API does. They are
    scaled to at most 2048 px and 3.75 MB, as before.
  - An agent that does not take pictures is told so in the message and looks at a picture with
    the new `scratch_view` tool. The chat says the pictures were not sent only in that case.
  - New editor command `ui.scratchView`: a picture in the scratch folder, as the model gets it.

- **The Assistant's conversation is kept with the project (#1169):** saving a design now writes
  the chat into its `.osd`. Opening the project shows the chat again, and you can go on where it
  stopped: your next message carries the earlier conversation to the assistant, with the Claude
  API, OpenAI-compatible endpoints and coding agents alike.
  - **What is kept:** your messages and the assistant's, notices, and each tool step as its
    short label. Not kept: pictures (a message that had attachments says so), the assistant's
    thinking, tool arguments and results, and never a key or token. Your home, temporary and
    scratch folders are written as `~`, `<temp>` and `<scratch>`.
  - **Going on:** the first message after opening sends the last part of the chat (up to 24,000
    characters, whole messages) as quoted text from the file. The assistant is told it is file
    content and not instructions, because a project may come from someone else. A coding agent
    starts a new session with that text; its own earlier tool results are not loaded.
  - **Your control:** "Save the chat with the project" in the Assistant settings and under the
    chat (on by default). Off, nothing is written, and a chat the file already kept is removed
    on its next save. New chat clears the conversation, so the next save keeps none.
  - **Tabs, New, Save As, recovery:** each tab keeps its own chat; New starts an empty one;
    Save As carries it; recovered designs bring theirs back.
  - **Unsaved changes:** while the chat is saved with the project, talking marks the design
    unsaved as an edit does: the title shows it, closing asks to save, and autosave keeps it.
    An untitled design with no objects is not marked by a chat alone.
  - **Older versions:** alpha 15 opens such a project normally and ignores the chat; saving it
    there drops the chat.
  - **Undo:** a reopened chat does not offer to undo changes from an earlier run of the program.
  - **Projects the assistant opens** (#1178): the opened file becomes the design's file, as with
    File ▸ Open, and a chat it kept stays in it; a save the assistant runs to a new name makes
    that the design's file, as Save As does.
